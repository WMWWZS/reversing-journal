# 10 · 寄存器入门：`rcx` 到底是什么

> 学汇编卡住的第一个坎，几乎都是「这些 r 开头的字母是什么」。
> 这一篇从零讲清楚，不需要任何前置知识。

## 一句话

**寄存器 = CPU 内部自带的 16 个小格子。**

CPU 要做任何计算，都必须先把数据搬进这些格子。汇编指令做的全部事情，就是在这些格子之间、以及格子和内存之间倒腾数据。

## 为什么要有寄存器

| | 速度 | 容量 |
|---|---|---|
| 寄存器 | 极快（< 1 纳秒，直接参与运算） | 每个 8 字节，一共 16 个 |
| 内存 | 慢（几十纳秒，要先寻址再读取） | 几十 GB |

CPU 不可能每次算加法都去内存里拿数——太慢了。所以设计成：**先把数据装进寄存器，再算。**

这就是为什么 `Player` 结构体在内存里，但 `p->hp - dmg` 这个计算过程中，`hp` 和 `dmg` 都会被临时搬进寄存器。

## x86-64 的 16 个通用寄存器

| 寄存器 | 传统名字含义 | 常见用途 |
|---|---|---|
| `rax` | **a**ccumulator（累加器） | **函数返回值**、临时计算 |
| `rbx` | **b**ase | 被调用者保存的临时值 |
| `rcx` | **c**ounter（计数器） | **第 1 个参数**、循环计数 |
| `rdx` | **d**ata | **第 2 个参数** |
| `rsi` | **s**ource **i**ndex | 字符串源地址 / 第 3 参数（Linux） |
| `rdi` | **d**estination **i**ndex | 字符串目的地址 / 第 4 参数（Linux） |
| `rbp` | **b**ase **p**ointer | **栈帧基址**（函数的"本地坐标系原点"） |
| `rsp` | **s**tack **p**ointer | **栈顶指针**（一直指向栈最上面） |
| `r8` – `r15` | 后来新增，没有传统名字 | 参数、临时值 |

> 名字不重要，**用途约定**才重要。下面那张调用约定表是必须背的。

## 同一个寄存器，四个名字

这是新手最容易懵的地方。`rax` 并不是只能叫 `rax`：

```
rax  ├─ 64 位：rax    （全名）
     ├─ 32 位：eax    （e = extended，低 32 位）
     ├─ 16 位：ax     （低 16 位）
     └─ 8  位：al（低 8 位）、ah（8~15 位）
```

| 64 位 | 32 位 | 16 位 | 8 位 |
|---|---|---|---|
| `rax` | `eax` | `ax` | `al` / `ah` |
| `rbx` | `ebx` | `bx` | `bl` / `bh` |
| `rcx` | `ecx` | `cx` | `cl` / `ch` |
| `rdx` | `edx` | `dx` | `dl` / `dh` |
| `rsi` | `esi` | `si` | `sil` |
| `rdi` | `edi` | `di` | `dil` |
| `rbp` | `ebp` | `bp` | `bpl` |
| `rsp` | `esp` | `sp` | `spl` |
| `r8`–`r15` | `r8d`–`r15d` | `r8w`–`r15w` | `r8b`–`r15b` |

**为什么搞这么复杂？** 因为 x86 是从 1978 年的 8086（16 位）一路演化来的，必须保持向后兼容。`ax` 在 8086 时代就有了，`eax` 是 80386 加的，`rax` 是 x86-64 加的。

### ⚠️ 一个必须知道的陷阱

```
mov eax, 0      ; 会把 rax 的高 32 位一起清零！
```

写 **32 位**寄存器时，CPU 会自动把**高 32 位清零**。写 16 位或 8 位则不会（保留其余位）。

这就是为什么你在反汇编里经常看到 `mov eax, ...` 而不是 `mov rax, ...`——编译器在利用这个特性顺手清零，省一条指令。

## 调用约定：为什么 `rcx` 是「第 1 个参数」

函数调用时，参数必须有个地方放。**约定**规定它们放在哪几个寄存器里：

### Windows x64（你分析的游戏几乎都是这个）

| 位置 | 放什么 |
|---|---|
| `rcx` | 第 1 个参数 |
| `rdx` | 第 2 个参数 |
| `r8` | 第 3 个参数 |
| `r9` | 第 4 个参数 |
| `[rsp+0x28]` 起 | 第 5 个及以后 |
| `rax` | 返回值 |

**记忆口诀：C D 8 9**（rcx, rdx, r8, r9）。

### Linux / macOS（System V AMD64）

| 位置 | 放什么 |
|---|---|
| `rdi` | 第 1 个 |
| `rsi` | 第 2 个 |
| `rdx` | 第 3 个 |
| `rcx` | 第 4 个 |
| `r8` / `r9` | 第 5 / 6 个 |

> 同样是 `rcx`，Windows 里是第 1 个参数，Linux 里是第 4 个。**分析前先确认平台。**

## 回到你正在看的代码

```asm
140001450  PUSH  RBP                  ; 保存调用者的 rbp
140001451  MOV   RBP, RSP             ; rbp = 当前栈顶，建立新栈帧
140001454  MOV   [RBP+p], RCX         ; ★ 把第 1 个参数存到栈上
140001458  MOV   [RBP+dmg], EDX       ; ★ 把第 2 个参数存到栈上
14000145b  MOV   RAX, [RBP+p]         ; 把 p 取回 rax
14000145f  MOV   EAX, [RAX]           ; 读 p 指向的内存 → hp
```

逐行翻译：

| 行 | 含义 |
|---|---|
| `PUSH RBP` | 把旧的栈帧基址压栈保存 |
| `MOV RBP, RSP` | 新的栈帧从这里开始 |
| `MOV [RBP+p], RCX` | **函数收到的第 1 个参数（在 RCX 里），存进栈上叫 `p` 的格子** |
| `MOV [RBP+dmg], EDX` | 第 2 个参数（在 EDX 里）存进栈上 |
| `MOV RAX, [RBP+p]` | 从栈上把 `p` 取回到 RAX |
| `MOV EAX, [RAX]` | 读 `p` 指向的第 0 个 int → 就是 `hp` |

**为什么函数一开始要先把参数存到栈上？** 因为 `-O0` 不优化，每个变量都有栈上的"家"（home），方便调试器查看。这也是为什么 `-O0` 的代码又长又好读，`-O2` 的代码又短又难读。

## Ghidra 里的 `in_RCX` 是什么

你在 Decompiler 里看到：

```c
int *in_RCX;     // 从 RCX 寄存器来的输入
int in_EDX;      // 从 EDX 寄存器来的输入
```

意思是：**「这个值是从 RCX 寄存器传进来的」**。`in_` 是 `input` 的缩写。

因为 Ghidra 没能把它和函数签名里的参数 `p` 对应上（前面讲过 `Unknown calling convention` 那个警告），所以只能按寄存器名字叫它。

**你做的事就是给它起个人名**——把 `in_RCX` 改成 `p`，代码立刻就通了。

## 记忆清单

必须条件反射的四件事：

1. **第 1 个参数在 `rcx`**（Windows）
2. **第 2 个参数在 `rdx`**
3. **返回值在 `rax`**
4. **`rsp` 是栈顶，`rbp` 是栈帧基址**

其余都可以查表。

## 自测

**1. 在一个 Windows 程序里，第 3 个参数在哪个寄存器？**

- 考点：调用约定
- 应明白：前 4 个依次是 rcx / rdx / r8 / r9
- 算会：你能不查表就说出来

**2. 执行 `mov ecx, 0` 之后，`rcx` 的值是多少？**

- 考点：32 位写入会清零高 32 位
- 应明白：`rcx` 整体变成 0，不是只改低 32 位
- 算会：你能解释为什么编译器爱用 `eax` 而不是 `rax`

**3. 为什么函数开头要把 `rcx` 存到栈上？**

- 考点：`-O0` 的变量存储策略
- 应明白：每个局部变量（包括参数）在栈上有个固定位置，方便调试
- 算会：你能说出 `-O2` 版为什么通常看不到这一步

**4. `in_RCX` 这个名字是谁起的？**

- 考点：反编译器如何标注寄存器来源
- 应明白：Ghidra 起的临时名，表示"值来自 RCX"
- 算会：你能说明为什么改名之后代码就变可读了
