# 16 · 什么时候真正需要"操作系统"和"网络"这两块

> 这份文档只回答两个问题：
> 1. 操作系统（[14](14-operating-system.md)）和网络（[15](15-network.md)、[06](06-network-protocol.md)）**什么时候才用得上**；
> 2. 能不能和内存主线**一块教**——能，但不能并成一条线，理由见 §4。

---

## 1. 一句话结论

| 领域 | 现在要不要 | 什么时候变成硬需求 |
|---|---|---|
| 操作系统 | **已经在用，只是没点名** | 写代码段补丁 / 做叠加层（07–09）时开始卡；做内核读写（10–11）时变成必须 |
| 网络 | **单机完全不需要** | 只有当你把目标换成**联机**游戏时；离线 bots / 单人存档走的是本地内存，一根网线都不用 |

**你现在打的 AssaultCube 离线 bots，不需要任何网络知识。**

---

## 2. 操作系统：三档，别一次学完

### 档 A · 已经在用（labs 00–06 每天都在碰）

| 你已经在做的动作 | 背后是哪块 OS 知识 | 在哪一节 |
|---|---|---|
| `OpenProcess` 要 `VM_READ / VM_WRITE / CREATE_THREAD` | 进程对象、句柄、访问权限（ACL） | 03 / 06 |
| `WriteProcessMemory` 必须配 `PROCESS_VM_OPERATION` | 虚拟内存、页保护位（改保护要先有权限） | 03 |
| `VirtualQueryEx` 只挑 `MEM_PRIVATE` 区域 | 用户地址空间布局：映像 / 堆 / 栈 / 保留区 | 04 |
| `VirtualAllocEx` + `PAGE_EXECUTE_READWRITE` | 页权限、为什么 RWX 是可疑信号 | 06 |
| 目标每 100ms 掉血，我们每 50ms 写 | 线程调度、竞态、谁后写谁赢 | 03 / 06 |
| `EnumProcessModules` 拿基址 | PE 头、模块映射（[09-pe-format](09-pe-format.md)） | 02–05 |
| 为什么 `-no-pie` 基址稳定、堆地址每次都变 | 映像重定位 / ASLR | 01 / 04 |

**这一档不需要"先学 OS 再回来"**——它已经发生了。缺的只是把名字对上：
下次跑 `04-pointer-chain` 时，把 `MEM_PRIVATE` 那块想成"堆"，把 `0x140000000` 想成"映像"，就够了。

### 档 B · 07–09 会卡住的地方

| 要做的事 | 需要补的 OS 知识 |
|---|---|
| 07 hook：改代码段指令 | `VirtualProtect` 改页保护、`FlushInstructionCache`、代码段只读属性 |
| 07 hook：IAT hook | PE 导入表结构、模块加载顺序（[09-pe-format](09-pe-format.md)） |
| 09 叠加层 | 窗口消息、D3D 呈现链、跨进程绘制（透明窗口 / 合成器） |

### 档 C · 10–11 才必须

| 要做的事 | 需要补的 OS 知识 |
|---|---|
| 理解反作弊为什么拦得住你 | 内核回调（`ObRegisterCallbacks` / `PsSetCreateProcessNotifyRoutine`）、句柄权限检查发生在内核 |
| 驱动读写 | 内核态/用户态边界、IRP 与 DeviceIoControl、驱动签名与 DSE |
| 物理内存 / DMA | CR3、页表遍历、IOMMU |

> 判据：**出现"内核对象 / 回调 / 驱动 / 物理地址"这几个词，才轮到档 C。**

## 3. 网络：只有联机才需要

| 场景 | 数值在哪算 | 需要网络知识吗 |
|---|---|---|
| 单人存档 / 离线 bots（**你现在的 AC**） | 本地内存 | **不需要** |
| 联机 · 客户端预测型 | 本地先算，服务端弱校验 | 需要：封包结构、seq/帧号、校验和重算 |
| 联机 · 服务端裁定型 | 服务端算，客户端只发输入 | 需要：权威边界、输入伪造、时间窗口 |
| 联机 · 回滚补偿型 | 服务端保存历史快照 | 需要：时间轴、重放、反重放（nonce/timestamp/seq） |
| 联机 · 加密协议 | — | 再加 TLS / 自定义加密 / 协议逆向 |

判据：**出现"另一台机器"或"服务器"这三个字，才轮到网络。**

---

## 4. 能不能一块教：能，但要分三种形式

并成一条线会出问题：网络的知识密度远高于内存主线，混在一起会把你刚建立的"读到数字—改掉—验证"的节奏冲散。建议这样排：

| 形式 | 频率 | 内容 | 例子 |
|---|---|---|---|
| **主线** | 每节 lab | 内存/代码这条线，遇到 OS 概念当场点名，不展开 | 06 里看到 RWX → 一句话说清页权限，继续写注入 |
| **小灶（10 分钟）** | 每次开头 | 只讲**当节 lab 会用到的那一个** OS 概念，并且必须配当时的证据 | 读 04 的 dump → 讲"私有内存 = 堆"；读 06 的分配地址 → 讲 RWX |
| **支线** | 主线到 07 之后 | 网络单独开一条，从"抓自己两个进程的 loopback 通信"起步 | 先抓包看结构，再谈校验和 |

**结论：OS 用"小灶"混进主线；网络不要混，等主线站稳再单开。**
