# 13 · 栈帧是什么（零基础版）

> 这一篇不用任何前置知识。看完你应该能指着 x64dbg 说清楚 `RSP`、`RBP`、`[RBP+0x10]` 分别在干嘛。

## 一、先问：程序为什么需要「临时空间」

函数执行时要存一些临时数据：

- 传进来的**参数**
- 自己定义的**局部变量**（比如 `int i;`）
- 干完活要**回到哪里**（返回地址）

这些东西放哪？不能放寄存器——寄存器只有 16 个，函数多了不够用。

所以程序在内存里划了一块区域专门放这些临时数据，叫**栈（stack）**。

## 二、栈：一摞盘子

想象一摞盘子：

- 你**只能从最上面放**新的
- 也**只能从最上面拿**走
- 中间的盘子碰不到

这叫「后进先出」（LIFO）。英文叫 stack，中文叫栈。

**为什么函数调用正好符合这个规律？**

```c
void A() { B(); }
void B() { C(); }
void C() { }
```

执行顺序：A 开始 → B 开始 → C 开始 → **C 结束** → B 结束 → A 结束。

最后开始的最先结束，跟「盘子」一模一样。所以用栈正合适。

## 三、栈帧：每个函数的一张「工作台」

每次调用一个函数，程序就在栈顶上给他划一块地方，这块地方叫**栈帧（stack frame）**。

比喻：

> 栈 = 一栋楼
> 栈帧 = 每个函数住的一间房间
> 房间里放着他自己的东西：参数、局部变量、返回地址、上一个房间的钥匙

函数结束，房间就还回去，下一个函数接着用。

**注意：函数多了，房间里是多层叠起来的。**

```text
调用 A 时：  [ A 的房间 ]
A 调用 B 后：[ A 的房间 ][ B 的房间 ]
B 调用 C 后：[ A 的房间 ][ B 的房间 ][ C 的房间 ]
C 结束后：  [ A 的房间 ][ B 的房间 ]
```

## 四、房间里装什么

一个栈帧里通常有这四样：

| 东西 | 为什么放这儿 |
|---|---|
| **返回地址** | 函数干完活要知道回哪去 |
| **保存的旧 RBP** | 记着上一个函数房间的位置，回来时要还 |
| **参数** | 调用者传进来的值 |
| **局部变量** | 函数自己定义的变量 |

## 五、两个指针：RSP 和 RBP

这是最容易懵的地方。用房间比喻：

### RSP = 「现在用到哪了」

栈顶指针。它一直指着**当前房间的最下沿**（栈往低地址长）。

每次 `PUSH`（往里放东西），`RSP` **减 8**（地址变小，栈变大）。
每次 `POP`（往外拿东西），`RSP` **加 8**。

### RBP = 「这间房间的门牌号」

栈帧基址指针。它指着**当前房间的一个固定位置**。

为什么需要它？因为 `RSP` 会随 `PUSH`/`POP` 不停变，用它定位变量很不方便。

有了固定的 `RBP`，就可以用**固定偏移**访问房间里的东西：

- `[RBP+0x10]` = 房间里第 1 号柜子（参数）
- `[RBP+0x18]` = 第 2 号柜子（另一个参数）
- `[RBP-0x4]` = 第 3 号柜子（局部变量）

**这些 `+0x10`、`-0x4` 就是你在反汇编里看到的那些数字。**

## 六、一张图看懂

```text
        高地址
        ┌──────────────────┐
        │   调用者的栈帧     │
        ├──────────────────┤
        │   返回地址         │ ← call 指令压进来的
        ├──────────────────┤
        │   旧的 RBP         │ ← push rbp 压进来的
        ├──────────────────┤ ← RBP 指向这里
        │   [RBP+0x10] 参数p │
        │   [RBP+0x18] 参数dmg│
        ├──────────────────┤
        │   局部变量         │ ← [RBP-0x4] 等
        ├──────────────────┤ ← RSP 指向这里（栈顶）
        │  （还能继续往下长） │
        低地址
```

## 七、对应到你刚才看到的汇编

```asm
140001450  PUSH  RBP           ; ① 把上一个房间的门牌号存起来
140001451  MOV   RBP, RSP      ; ② 挂上自己的门牌：从现在起这是"我的房间"
140001454  MOV   [RBP+0x10],RCX ; ③ 把参数1放进自己房间的1号柜
140001458  MOV   [RBP+0x18],EDX ; ④ 把参数2放进2号柜
```

逐条翻译成人话：

| 指令 | 人话 |
|---|---|
| `PUSH RBP` | 先把上一个函数的门牌号记下来，等会要还 |
| `MOV RBP,RSP` | 好，从这个位置开始算我的房间 |
| `MOV [RBP+0x10],RCX` | 第 1 个参数（在 RCX 里）放到我房间 1 号柜 |
| `MOV [RBP+0x18],EDX` | 第 2 个参数放到 2 号柜 |

## 八、函数结束时房间怎么了

函数末尾通常是这样：

```asm
POP  RBP       ; 把门牌号还给上一个函数
RET            ; 跳回返回地址，继续执行调用者
```

- `POP RBP`：房间还原
- `RET`：拿返回地址跳回去
- `RSP` 自动回到调用前的位置

**所以函数返回后，它的局部变量就"没了"**——不是说内存被擦掉，而是那块地方被标记为可复用，下一个函数会覆盖它。

> 这是很多 bug 的来源：**返回一个指向局部变量的指针**，函数一结束，那块内存就可能是别人的了。

## 九、为什么逆向必须懂这个

1. 看到 `[RBP+0x10]` → 知道这是在访问**这个函数的参数**
2. 看到 `[RBP-0x8]` → 知道这是**局部变量**
3. 看到 `PUSH` / `POP` → 知道栈在长还是在缩
4. 看到 `RSP` 突变 → 知道函数在分配/释放空间

**没有栈帧，`[rbp+0x10]` 这种写法就只是无意义的数字。**

## 十、常见疑问

**Q：为什么栈往"低地址"长？**
A：历史设计选择，没有深层原因。所以"往上放盘子"其实是地址变小。

**Q：所有函数都有栈帧吗？**
A：不一定。编译器优化后（`-O2`）可能省略 `RBP`，直接用 `RSP` 偏移，甚至全用寄存器。这叫"省略帧指针"。

**Q：递归函数不会撑爆吗？**
A：会。每层递归一个栈帧，层数太多就会"栈溢出"（stack overflow）。

**Q：栈有多大？**
A：Windows 默认每个线程 1 MB 左右。所以递归不能太深。

## 自测

**1. `PUSH RBP` 执行后，`RSP` 变大还是变小？**

- 考点：栈的生长方向
- 应明白：栈向低地址生长，`PUSH` 让 `RSP` **减小 8**
- 算会：你能解释"地址变小但栈变大"

**2. 为什么函数返回后不能再用它的局部变量？**

- 考点：栈帧的生命周期
- 应明白：栈帧被"归还"，那块内存会被下一个函数覆盖
- 算会：你能说出"内存还在，但已经不属于你了"

**3. `[RBP+0x10]` 和 `[RBP-0x4]` 有什么区别？**

- 考点：栈帧内部分区
- 应明白：`+` 方向是调用者准备的数据（参数），`-` 方向是函数自己的局部变量
- 算会：你能看着偏移猜出它是参数还是局部变量
