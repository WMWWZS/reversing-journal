# 实验 03 · 跨进程写入：读 → 写 → 保持

> 前两节只做了两件事：算偏移、读内存。
> 这一节第一次**写**进去。
>
> 写之前先把这件事的性质说清楚：
>
> **你写的每一行代码，x64dbg 的 Dump 面板和 Cheat Engine 的手动改值窗口里都已经有了。**
> 跨进程读写内存不是黑魔法，是调试器的基本功。区别只在于调试器给你界面，
> 这一节要你自己把 `OpenProcess` / `ReadProcessMemory` / `WriteProcessMemory` 串起来。
>
> 学会它，你才算真的理解"一个进程怎样碰另一个进程的内存"。

---

## 0. 一个必须先扭转的观念

初学者以为改数值是"改游戏"。

不是。目标进程根本不知道你在。你只是往它的一块内存里塞了 4 个字节，
它下一帧自己读出来，就以为那是它自己算出来的值。**它没被骗，它只是信了自己的内存。**

所以这一节要学的是三件事，按顺序：

```
定位（这个字段在哪个地址）  ->  读写（四个字节怎么进去）  ->  保持（它总是被重算怎么办）
```

后面所有内存类工具，无论叫什么名字，都是这三步的排列组合。
自瞄写的是鼠标坐标，透视读的是敌我坐标，改体力改的是计时器字段——**动词只有读和写。**

## 1. 这一节新增的两样东西

| | 实验 02 | 实验 03 |
|---|---|---|
| 权限 | `PROCESS_VM_READ` | 加 `PROCESS_VM_WRITE` + `PROCESS_VM_OPERATION` |
| API | `ReadProcessMemory` | 加 `WriteProcessMemory` |
| 地址来源 | 搜一个已知的值（92.5） | 搜字符串特征（`"bot-1"`） |
| 靶子 | 打印三帧就停住 | **一直在跑，每 100ms 掉 2.5 血** |

`PROCESS_VM_OPERATION` 不是多余的：`WriteProcessMemory` 内部要改目标进程的页保护
（把只读页临时改成可写），这个动作需要它。少了它，写入直接失败，`GetLastError` = 5。

## 2. 为什么不能写死 `0x7050`

实验 02 你测出 `hp` 在 `base + 0x7050`。这次为什么还去扫字符串？

因为**写死的偏移是脆的**：

- 在 `entity.h` 里加一行变量 → 后面所有字段整体挪位
- 换编译器版本、换优化等级 → 布局可能变
- 结构体放在堆上时，每次启动地址都不一样（下一节就讲这个）
- 真实程序一更新，`0x1A4B2C0` 这种绝对地址 100% 会变；**字符串一般还在**

所以要养成习惯：**偏移用来算，特征用来找。**

这一节用的是特征扫描里最简单的一种——**字符串特征（signature scan）**：

```
在整个模块映像里搜  "bot-1\0"      -> 命中，那是 name 字段
name 在 entity + 0x18，hp 在 entity + 0x10
所以 hp 地址 = 命中地址 - 0x08
```

`-0x08` 是从结构体布局推出来的，不是猜的。工业级做法完全同理，只是特征换成
`48 8B 05 ?? ?? ?? ?? 48 85 C0` 这种指令字节序列（叫 AOB / pattern scan，第 5 节专门做）。

## 3. 跑起来

双击 `run.bat`。它会：

1. 编译 `target.exe`（被观察的样本）和 `memtool.exe`（工具）
2. 另开一个窗口跑 `target.exe` —— **那个窗口是你的观测窗口，别关**
3. 在当前窗口依次跑：只读 → 写一次 → 读回 → 保持 10 秒

也可以手动两个窗口：

```bat
REM 窗口 A
cd labs\03-write-memory
target.exe

REM 窗口 B
cd labs\03-write-memory
memtool.exe read
memtool.exe write 9999
memtool.exe hold 9999 10
```

看到 `target.exe` 窗口里 `[0] bot-1 hp = 9999.0` **停住不动**、而右下角 `frame` 还在涨，
就成功了。那一瞬间你手上就有了一个能改另一个进程数据的程序。

## 4. 本机实测输出（2026-11-25，真实跑出来的）

**A. 只读，样本已跑 3 秒**

```
[+] target.exe pid = 51488
[+] module base 0000000140000000  size 0x14000
[+] "bot-1" found at  base + 0x7058
[+] name field     base + 0x7058   (entity + 0x18)
[+] hp   field     base + 0x7050   (entity + 0x10 = name -8)
[+] current hp = 65
```

**B. 1.2 秒后再读**

```
[+] current hp = 37.5
```

`65 - 37.5 = 27.5`，`27.5 / 2.5 = 11` 帧，`11 × 100ms = 1.1s`。**和真实时间对得上。**
这条不是废话——它证明你锁定的地址**真的是那个每帧在变的量**，不是撞上的野数据。

**C. 写一次 9999，2 秒后再读**

```
[+] wrote 9999  ->  readback = 9999     <- 写成功了
[+] current hp = 9954                   <- 但已经掉了 45
```

`45 / 2.5 = 18` 帧 = 1.8 秒。也就是说：**你写完的下一个 100ms，样本就把它算回去了。**

这是新手最大的错觉："我改成功了"。你看到的 `readback = 9999` 只说明那 1 毫秒里它是 9999。
**内存是活的，不是硬盘上的文件。**

**D. 保持 3 秒，然后松手**

```
[+] holding hp = 9999 for 3 s (60 writes, every 50 ms)
    t =  0 s   hp = 9999
    t =  1 s   hp = 9999
    t =  2 s   hp = 9999
[+] stop writing now.
[+] hp 0.4 s later = 9989   <- 一松手立刻回到目标自己的计算
```

`9989` = 9999 − 10，正好 4 帧 × 2.5，正好 0.4 秒。**速度、帧率、掉血量，全部自洽。**

> 四个数字互相对得上，才叫证据。一个数字漂亮，可能只是巧合。

## 5. 为什么"保持"要循环写

因为你在和**目标的事件循环**抢同一块内存。

```
目标：  hp -= 2.5        每 100 ms
你  ：  hp = 9999        每 50 ms
```

谁后写谁赢。你写得比它快，屏幕上就一直是 9999（偶尔闪一下原值，肉眼看不出来）。

所以"锁定数值"从来不是一次操作，是**一个持续运行的循环**。所有"锁定体力""无限资源"
"数值不变"的功能，本质都是这个循环。理解这一点，你就理解了这一整类工具 90% 的实现。

## 6. 自己动手（三个，按顺序做）

先猜，再跑，猜错写下来。

**实验 A · 改第二个实体**

`memtool.exe write` 只改 `[0]`。现在改 `[1]` 的 hp。
提示：实体步长 `sizeof(Entity) = 0x28`，`[1].hp = base + 0x7050 + 0x28`。
改完跑，看 `target.exe` 窗口里第二个 bot 是不是也一样停住。
（能不能一次保持四个？先把循环写出来，改成遍历 4 个实体。）

**实验 B · 改字符串，证明你真在改数据**

在 `memtool.c` 里加一个模式：把 `bot-1` 的 `name` 改成 `renamed`（写 16 字节，注意补 `\0`）。
跑完抬头看 `target.exe` 窗口——`[0] bot-1` 变成了 `[0] renamed`。
**这一条最重要**：它让你亲眼看见"内存里的数据"和"屏幕上的显示"是同一份东西。

**实验 C · 把保持的频率调慢**

把 `Sleep(50)` 改成 `Sleep(2000)`，保持 10 秒。看 `target.exe` 窗口里的数字——
它会**锯齿状**跳：掉一会儿，被你拉回 9999，再掉，再拉回。
你立刻会明白：保持效果 = 间隔 × 值的组合，不是魔法。

## 8. 常见坑

- **`GetLastError = 5`**：`OpenProcess` 少了 `PROCESS_VM_WRITE | PROCESS_VM_OPERATION`。
- **写进去立刻变回去**：正常，你只写了一次。见 §5。
- **`target.exe not found`**：样本没起，或进程名不对。`find_pid` 是**全名匹配**（`target.exe`）。
- **写 float 却给了 int**：`9999` 和 `9999.0f` 在内存里是**完全不同的 4 个字节**。
  `9999` 当 float 解 = `1.4e-41`，一个接近 0 的垃圾值。这是新手第 1 名错误。
- **`-no-pie` 忘了加**：`target.exe` 每次启动基址变，`base + 0x7058` 就找错了位。
  本目录的编译命令已经带上，别手抖删掉。
- **改了结构体没改 `memtool.c` 的常量**：`NAME_OFF_FROM_ENTITY` / `HP_FROM_NAME_DELTA`
  必须和 `entity.h` 同步。这就是"注释是承诺"的第二次现形。

## 9. 真实软件比这多三个问题（提前知道，别踩空）

你现在这套在自己的靶子上百分百有效。换成任何有工程量的真实程序，会依次遇到三件事，
后面每一节都对应一件：

1. **地址不稳定**：结构体在堆上，每次启动都变，偏移要顺着一串指针追
   （第 4 节：指针链）。
2. **数据会被重算**：同一个量存在两个地方交叉校验，或者每帧从别处重算一遍，
   单点写入无效，得改**代码**而不是改数据（第 6 节：代码注入与 hook）。
3. **程序会检查自己**：句柄扫描、模块枚举、`.text` 段哈希、时序检测——
   这些是现代软件的自我保护机制，属于**防护设计**，值得单独学它怎么工作
   （第 10 节：完整性校验与反调试；第 11 节：内核态内存访问）。

**顺序不能跳。** 指针链没学，直接抄内核驱动代码，你只会得到一坨跑不起来的黑箱。
