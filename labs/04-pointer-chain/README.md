# 实验 04 · 指针链：地址每次启动都会变，怎么还能找到它

> 实验 03 里你写死了 `base + 0x7050`，能用，因为那个数组是全局的。
> 这一节把数组搬到堆上——**同一个程序，地址每次启动都不一样**。
> 你手上唯一稳定的东西，是模块里那个 8 字节的格子。
>
> 这一节要学的就一件事：**怎么从那个格子，一步一步走到字段。**
> 这就是"指针链"，也是所有真实程序分析的第一个门槛。

## 0.5 游戏里这对应什么

| 游戏里 | 进程里 | 具体到字节 |
|---|---|---|
| 游戏「这一局」的世界 | `g_world` 槽位（模块里，地址固定） | 8 字节，存着 World 的堆地址 |
| 场景里的怪物列表 | `World->units` | World +0x00，8 字节 |
| 第 k 只怪 | `units + k*0x28` | 步长 0x28 |
| 它的血 | `+0x10` | float 4 字节 |
| **每次重开游戏地址都变** | 堆对象重建 | 所以不能写死地址，只能走链 |

链的价值：**从一个"永远在"的槽位，走到一个"每次都变"的字段。**

## 0. 先看现象（本机两次运行的真实输出）

```
slot   &g_world        = 0000000140007030   <- fixed: module base + offset
heap   g_world         = 0000000000101E20   <- heap: different every run
heap   g_world->units  = 0000000000101300   <- heap: different every run
layout: World sizeof=0x10 units@+0x0 | Entity sizeof=0x28 hp@+0x10 name@+0x18
```

关掉再开一次：

```
slot   &g_world        = 0000000140007030   <- 一模一样
heap   g_world         = 0000000000681E60   <- 0x101E20 -> 0x681E60
heap   g_world->units  = 0000000000681300   <- 0x101300 -> 0x681300
```

**结论一句话**：模块里的格子不动，堆里的东西每次都搬家。

所以实验 03 那套 `base + 0x7050` 在这里 100% 失效。你必须接受一个新事实：
**你要的那个地址不是常数，是一条路径的终点。**

## 1. 指针到底是什么

不是"高级特性"，不是"引用"，就是一句话：

> **一个 8 字节的格子，里面装的是另一个格子的地址。**

64 位程序里指针固定 8 字节（32 位程序里是 4 字节——记住这条，AssaultCube 就是 32 位）。

所以内存里长这样：

```
地址 0x140007030   ┌──────────────────┐
（模块 .data）      │ 0x0000000000101E20│  <- 8 字节，是一个地址
                   └──────────────────┘
                                │
                                ▼
地址 0x101E20      ┌──────────────────┐
（堆，World）       │ 0x0000000000101300│  <- 又是 8 字节，又是一个地址
                   │ count = 4        │
                   └──────────────────┘
                                │
                                ▼
地址 0x101300      ┌──────────────────┐
（堆，Entity[0]）   │ id = 1           │ +0x00
                   │ pos[3]           │ +0x04
                   │ hp = 82.5        │ +0x10   <- 你要的就是这 4 个字节
                   │ team, pad        │ +0x14
                   │ "bot-1"          │ +0x18
                   └──────────────────┘
```

走链的动作，抽象成一句话：

```
每跳一次 = 读 8 个字节（当前格子里的地址） + 加一个偏移（到下一个格子）
最后一跳 = 加完偏移之后，读 4 个字节（float）
```

"三级指针"就是这句话重复三次。没有别的含义。

## 2. 怎么把链挖出来（这一节真正的难点）

### 2.1 我第一版写错了，错得很有教育意义

第一版思路：先从名字 `bot-1` 找到实体数组，再**在模块映像里**搜"哪个格子存着这个地址"。

结果：

```
[*] auto mode: any float that looks like an hp (0 <= v <= 100, multiple of 2.5)
[-] no chain found (tried 401 candidate floats).
```

401 个候选全失败。原因很简单，一句话：

> **存着 `units` 地址的那个格子，在堆里的 `World` 结构体里面。**
> 模块映像里根本没有这个值，你在模块里搜到天荒地老也搜不到。

这就是为什么 Cheat Engine 的 pointer scan 要扫**整个进程的可读写内存**，
而不是只扫 exe。这不是它笨，是因为指针可能躺在任何地方。

### 2.2 正确做法：扫全进程

```
1) 枚举进程的所有内存区域        VirtualQueryEx
2) 只要 MEM_COMMIT + MEM_PRIVATE + 可读的（堆、栈）
3) 每块 ReadProcessMemory 下来，形成一个"快照"
4) 在快照里搜 8 字节的值 == units  -> 命中点就是 World 里的那个格子
5) 再在模块映像里搜 8 字节的值 == World -> 命中点就是全局指针槽
6) 用推出来的链回头解析，必须精确回到同一个地址
```

第 6 步是判定标准，不能省。**能算回去才叫找到，否则只是撞上了巧合。**

### 2.3 两条入口

`chain.exe find` 从名字进去：搜字符串 `"bot-1"` → 那就是 `units + 0x18`。

`chain.exe find 82.5` 从数值进去：搜 float 82.5 → 减去 `0x10` 就是某个实体。
这条更接近你以后在真实程序里的做法（你通常先有值，再有结构）。

两条路最后都要过同一关：**验证**。

## 4. 本机实测（2026-11-25，真实输出）

```
[+] module base 0000000140000000  size 0x14000
[+] dumped 7 private region(s), 143360 bytes total
[*] mode: by name string "bot-1" (search every private region)
[+] units (entity array) = 00000000007D1190
[+] names verified: bot-1..bot-4 at units+0x18, stride 0x28

[+] World  = 00000000007D1910   (heap; holds units at +0x00)
[+] g_world slot = base + 0x7030   (module; holds World)
[+] chain  = [base+0x7030] -> +0x00 -> +0*0x28 + 0x10
[hop 1] [0000000140007030] = 00000000007D1910   (World, heap)
[hop 2] [00000000007D1910+0x00] = 00000000007D1190   (units, heap)
[field] units + 0*0x28 + 0x10 = 00000000007D11A0
[+] verify = hp reads 82.5 at 00000000007D11A0
```

用挖出来的链读第三个实体：

```
[hop 1] [0000000140007030] = 00000000007D1910
[hop 2] [00000000007D1910+0x00] = 00000000007D1190
[field] units + 3*0x28 + 0x10 = 00000000007D1218
[+] hp[3] = 50
```

沿链保持 2 秒：

```
[+] holding hp[0] = 9999 for 2 s (40 writes)
    t =  0 s   hp = 9999
    t =  1 s   hp = 9999
[+] hp 0.4 s later = 9989   <- released, target recomputes again
```

**三条证据互相咬合**：
`units + 3*0x28 + 0x10` 算出来是 `0x7D1218`，读出来是 50；
而第四个实体初始 70，掉了 20 就是 8 帧 × 2.5 —— 和它已经跑的帧数一致。
再重启一次靶子，你会看到 `slot` 还是 `0x7030`，而两个 heap 地址全变。

## 5. 自己动手

先猜，再跑。

**实验 A · 第三个实体**
不动代码，用 `chain.exe read 0x7030 2` 读 `[2]`。先纸上算地址：
`units + 2*0x28 + 0x10` 应该是多少？再对照输出。

**实验 B · 给链再加一级**
改 `target.c`：在 `World` 外面再包一层 `Game`，`static Game *g_game;`，
`Game` 里放一个 `World *world;`。于是链变成
`[base+slot] -> +0x00 -> +0x00 -> +0x28*k + 0x10`。
改完 `chain.exe find` 会挂掉（它只认两跳）——**这就是你要自己动手改的地方**：
在 `resolve()` 里加一跳，在 `solve_chain()` 里多搜一层。
能做出来，你就真的会指针扫描了。

**实验 C · 证明链比地址长寿**
记下 `chain.exe find` 输出的 slot 偏移 → 关掉靶子 → 重新开 → 再跑 `chain.exe read 0x<slot>`。
slot 没变、heap 全变、hp 又能读到。**这一条是这一节的结论本身。**

## 7. 常见坑

- **忘了指针是 8 字节**：64 位下用 4 字节读指针，读到的是半个地址，后面全错。
- **忘了中间那一跳**：`base+slot` 读出来是 World 的地址，不是 units 的地址。少读一次直接偏到天上去。
- **`ReadProcessMemory` 返回失败但你没检查**：链断了通常是地址无效，不是权限。要把 `GetLastError` 打出来。
- **扫内存只扫了模块**：见 §2.1，这是本节最重要的坑。
- **`VirtualQueryEx` 忘了跳过 `PAGE_NOACCESS`/`PAGE_GUARD`**：会一直读失败，或者踩到保留页。
- **把"指针"当成"值"**：`0x7D1190` 是地址，不是数字。你读 8 字节得到它，再拿它当地址去读，才叫解引用。
- **`-no-pie` 让你以为地址是稳定的**：这里稳定的是**模块里的槽位**，不是堆。
  真实游戏里连模块基址都可能变（ASLR），所以真实链条第一跳还要再减一次模块基址。
