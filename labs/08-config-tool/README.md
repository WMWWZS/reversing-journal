# 实验 08 · 配置驱动 + 4 字节指针

> 前面 00–06 的工具全都把 `target.exe`、`0x7030`、8 字节指针**写死在代码里**。
> 这一节把这三样搬到 `config.txt`，再加一条 `ptr_size=4` 分支——
> **做完之后，同一份工具就能指向任何 64 位或 32 位单机游戏。**

---

## 1. 为什么必须先解决"指针宽度"

| 目标 | 指针字节数 | 地址范围 |
|---|---|---|
| 64 位进程（我们所有靶子、多数新游戏） | **8** | 0x0000000140000000 这种 |
| 32 位进程（AssaultCube、很多老游戏） | **4** | 0x00400000 / 0x10000000 这种 |

读错宽度的后果不是"读不到"，而是**读出一个看起来合理的假地址**，然后一路错下去。

实测（把 32 位靶子当 64 位读）：

```
[1] [base+0x7040] 读 8 字节 = 0x10000000
[2] [0x10000000 + 0x0] 读 8 字节 = 0x411000000     <- 多读了 4 字节，把 count 也吞进来了
[3] 0x411000000 + 0x10 = 0x411000010
[-] 字段地址 0x411000010 读不出来：指针宽度或偏移写错了？
```

**这就是为什么真实工具的第一个配置项永远是位数。**

---

## 2. 没有 32 位编译器，怎么验

本机只有 `x86_64-w64-mingw32` 的 gcc（`-m32` 链接直接失败），所以做了个等价靶子
`target32sim.c`：64 位进程，但

- 模块里的槽位是 `uint32_t`（4 字节）
- `World` / `Entity` 用 `VirtualAlloc((void*)0x10000000, ...)` 分配在 **4GB 以下**
- 指针字段全部用 `uint32_t` 存

这正是 32 位进程的内存形态。工具用 `ptr_size=4` 去读，就能走通。

---

## 3. 配置格式

```ini
# 目标进程名（任务管理器里那个）
process=target32sim.exe
# 模块内的指针槽偏移
slot=0x7040
# 目标里的指针宽度：8 = 64 位，4 = 32 位
ptr_size=4
# 跳序列：最后一段只加偏移；中间每段"加偏移再读指针"
hops=0x00,0x10
# 字段类型：float / int32
type=float
# 可选：数组步长与下标
stride=0x28
index=0
```

解析规则（程序里逐条对应）：

```
a = 模块基址 + slot
p = 读 ptr_size 字节(a)                第 1 次读
对 hops[0..n-2]:  p = 读 ptr_size 字节(p + hops[i])
字段地址 = p + hops[n-1] + index * stride
值 = 读 type 个字节(字段地址)
```

## 4. 实测（同一份 exe，两份配置）

**64 位靶子（lab04 的 target.exe）**

```
[+] 配置 config-64.txt：process=target.exe slot=0x7030 ptr_size=8 hops=2 段 type=float
[1] [base+0x7030] 读 8 字节 = 0x67EB60
[2] [0x67EB60 + 0x0] 读 8 字节 = 0x681310
[3] 0x681310 + 0x10 = 0x681320   <- 字段地址
[+] 当前值 = 82.5
[+] 写入 9999，回读 = 9999
```

**32 位模拟靶子（target32sim.exe）**

```
[+] 配置 config-32.txt：process=target32sim.exe slot=0x7040 ptr_size=4 hops=2 段 type=float
[1] [base+0x7040] 读 4 字节 = 0x10000000
[2] [0x10000000 + 0x0] 读 4 字节 = 0x11000000
[3] 0x11000000 + 0x10 = 0x11000010   <- 字段地址
[+] 当前值 = 87.5
[+] 写入 500，回读 = 500
```

**同一个 `chaincfg.exe`，只换配置。** 这就是这一节要的东西。

---

## 5. 怎么用到真实游戏上

以 AssaultCube 为例（32 位）：

1. CE 里正常找血量，冻结一次，确认你找对了；
2. 右键"找出是什么访问了这个地址"，看它用的是哪个静态指针；
3. Pointer scan 反推出 `[base+静态偏移] → 各跳偏移`；
4. 把结果抄进 `config-ac.txt`（参考 `config-ac-example.txt`）：
   ```ini
   process=ac_client.exe
   slot=0x<你扫出来的静态偏移>
   ptr_size=4
   hops=0x<跳1>,0x<跳2>
   type=float
   ```
5. `chaincfg.exe read config-ac.txt` —— 读得出血量就说明通了；
6. 关掉游戏重开，再跑一次。**能重算，才算成功。**

## 6. 判定标准

> 给一个新目标（64 位或 32 位），只看配置就能读到指定字段；
> 并且能解释"为什么把 ptr_size 从 4 改成 8 会读出 0x411000000 这种假地址"。

---

## 7. 常见坑

- **模块基址对 32 位目标也有效**：`EnumProcessModules` 在 WOW64 下返回的就是目标自己的模块表，
  64 位工具拿到的基址（如 `0x00400000`）可以直接用。
- **`ptr_size` 只影响指针，不影响字段**：HP 是 4 字节 float，跟指针宽度无关。
- **`slot` 是模块内偏移，不是绝对地址**：因为模块基址每次可能变（ASLR）。
- **32 位目标里别读 8 字节指针**：会读到一个"拼起来"的假值（实测 `0x411000000`）。
- **`hops` 的个数 = 读指针次数**：n 段 hops 对应 n 次读（含第 1 次 slot 读），
  最后一段只加偏移。数错一段，地址就飞了。
