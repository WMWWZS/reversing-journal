# 实验 00 · 先把地基铺平：地址、偏移、字节、跨进程

> 这个目录是回头补的地基。01~04 卡住的地方，全在下面这五步里。
> 每一步都是一个能独立跑的小程序，输出**中文**，数字都能自己对上。

| 文件 | 回答的问题 | 一句话结论 |
|---|---|---|
| `step1.c` | 地址、指针到底是什么 | 地址 = 格子编号；指针 = 装着编号的格子（8 字节） |
| `step2.c` | `+0x10` 哪来的 | 偏移 = 前面字段的字节数累加：`4 + 12 = 16 = 0x10` |
| `step3.c` | `p` 和 `hp` 什么关系 | 只有一份编号的拷贝，没有绑定；换掉编号，目标就换 |
| `step4.c` | `92.5` 为什么是 `00 00 B9 42` | float 4 字节，符号 1 + 指数 8 + 尾数 23，低位在前 |
| `step5-target.c` + `step5-reader.c` | 跨进程读取是什么 | `ReadProcessMemory` = memcpy + 一个 handle；拷贝是快照 |

## 这个目录踩出来的两条硬规则

**1. 中文输出要编译参数，不是把中文删掉。**

源码存 UTF-8，直接 `printf` 中文到 GBK(936) 控制台 → 乱码（`娌℃湁鍔` 这种）。
正确做法是保留中文、编译时加一句：

```bat
gcc -fexec-charset=GBK -g -O0 -Wall -o step1.exe step1.c
```

编译器会把字符串字面量转成 GBK 写进 exe，936 控制台就正常显示。
不加这个参数，或者 `printf` 里只留 ASCII，两者选一个——**千万别只做一半**。

**2. `.bat` 里不要写中文。**

cmd.exe 按 OEM 码页读批处理，UTF-8 的中文会变成乱码字节被当命令执行。
所以本目录的 `.bat` 全部纯 ASCII，连 `pause` 都换成了 `set /p`（`pause` 会打印中文提示）。
