# Lab 06 · crackme 01：定位并读懂校验逻辑

对应阶段：[第 3–4 周 · PE 结构与工具熟练](../../docs/00-roadmap.md)
产出目标：`writeups/` 里的第 1 篇 crackme 题解

## 目的

1. 练「从线索定位校验函数」的完整路径：字符串 → 交叉引用 → 反编译
2. 亲手踩一次**假字符串**的坑，建立「字符串只是线索，不是结论」的直觉
3. 读懂「逐字节异或比较」这种最常见的轻量保护，并反推出原文
4. 对比 `-O0 -g` / `-O2` / `-O2 -s` 三个版本，看清符号和优化各自抹掉了什么

| 文件 | 作用 |

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

会生成：

| 文件 | 编译命令 | 难度 | 用途 |
|---|---|:---:|---|

```
C:\...\06-crackme01> .\crackme_O2s.exe
key> 12345678

C:\...\06-crackme01> .\crackme_O2s.exe
key> xxxxxxxx
```

那 8 个 `x` 就是你要找的东西。

## 分析路线

### 第 1 步：先看轮廓，别急着读代码

```powershell
objdump -f .\crackme_O2s.exe
objdump -p .\crackme_O2s.exe | Select-String 'DLL Name|fgets|puts|strlen|GetEnvironment'
```

要回答三个问题：

- 入口地址是多少？PE 默认基址是多少？（提示：`0x140000000`）
- 它导入了哪些函数？**哪些是「读输入」的，哪些是「比内容」的？**
- 有没有导入 `GetEnvironmentVariable` 之类的环境变量相关函数？为什么一个 crackme 需要这个？

### 第 2 步：Ghidra 里从字符串摸进去

1. 导入 `crackme_O2s.exe`，分析用默认选项
2. `Search` → `Program Text` 搜 `key>`（也可以直接看 `Defined Strings` 窗口）
3. 找到引用它的函数 → 右键 `References` → `Show References to`
4. 落点就是 `main`

### 第 3 步：读那个比较循环

`Decompiler` 里应该能看到类似这样的结构（变量名是我换过的，你看到的会是 `local_xx`）：

```c
if (strlen(input) == 8) {
    for (i = 0; i < 8; i = i + 1) {
        if ((input[i] ^ K) != table[i]) goto fail;
    }
    success;
}
```

要看清三件事：**长度是多少、异或的常量是多少、比较的表在哪**。

### 第 4 步：逆运算

异或是对称的：`a ^ k ^ k == a`。所以拿到 `K` 和 `table`，把表里的字节按 `^ K` 逐个还原，就是原文。

`table` 在 Ghidra 里是一串没什么意义的字节，不会出现在字符串列表里——因为它不可打印。

> **注意那条 `ghidra42`。** 它是诱饵：只在设置了 `CRACKME_DEBUG` 环境变量时才会被打印，和真正校验的路径毫无关系。真实软件里这种死代码、过期提示、日志文案遍地都是，**顺着字符串找到的东西，必须用交叉引用和上下文验证一遍。**

### 第 5 步：动态验证

拿到答案后，回到 `-O0 -g` 版本用 gdb 单步确认判断点：

```powershell
gdb -q .\crackme_O0.exe
# b verify
# run
# 输入任意值，在比较处看寄存器
```

或者用 x64dbg 载入 `crackme_O2s.exe`，在 `strlen` / `fgets` 返回处下断点往回跟。

## 自测题

> 每道题都标注：**考点** · **做完你应该明白什么** · **怎么算真的会了**。
> 先自己答，再对照。

### 1. `.rdata` 里的 `ghidra42` 为什么不是答案？

- **考点**：字符串是线索，不是结论
- **应明白**：可打印字符串只说明「程序里存在这段文本」，**不能证明它参与校验**。必须用交叉引用确认它被哪段逻辑使用
- **算会**：你能说清用什么操作（`Show References to`）证明它只在 debug 分支被引用
- **常见错误**：搜到字符串就当成答案，不验证就下结论

### 2. 密文表在哪个节？为什么没出现在 `Defined Strings` 里？

- **考点**：节区语义 + 数据的可打印性
- **应明白**：`.rdata` 存只读数据；Ghidra 的 `Defined Strings` 只列「可打印 + 有终止符」的字节串。密文字节不可打印，**所以不会出现在字符串列表里，但它确实在内存中**
- **算会**：你能从比较指令出发用交叉引用追到表的地址，并把那 8 个字节 dump 出来

### 3. `-O2` 版本里 `strlen(input) != 8` 这条判断还在吗？

- **考点**：优化如何替换库函数与常量判断
- **应明白**：`-O2` 常把 `strlen` 内联成「扫描 0 字节」的循环，或把长度判断折叠进其它比较。**`call strlen` 可能消失，但语义还在**
- **算会**：你能在 `-O2` 版本里指出等价的长度检查位置，即使它已经不调用 `strlen`

### 4. `-O2 -s` 版本里你怎么从入口找到 `main`？

- **考点**：没有符号时的入口导航
- **应明白**：PE 入口是 CRT 启动代码，最终会调用 `main`。路径通常是
  `entry → __tmainCRTStartup / __scrt_common_main → main`
  但实战中更常用「字符串 / API 反查」绕过这条长链
- **算会**：你能写出**实际走过的**调用链（带地址），而不是「我觉得应该是这样」

### 5. 把 `^ 0x3F` 换成 `+ 0x3F`，还原方法要怎么改？

- **考点**：可逆运算的性质
- **应明白**：XOR 自反（`a ^ b ^ b == a`），所以**同一个常量既能加密也能解密**；加法要用减法还原，而且涉及进位，逐字节独立还原会更容易出错
- **算会**：你能说清「为什么 XOR 是轻量保护的首选」，以及换成加法后具体要改哪一步
