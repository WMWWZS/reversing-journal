## 0.5 游戏里这对应什么

| 游戏里 | 进程里 | 具体到字节 |

| 「我要让血量自己保持住」 | 在目标里起一个线程 | `CreateRemoteThread` |

## 1. 为什么非得进去

外部写：

```
你：hp = 9999        （一次）
目标：hp -= 2.5      （每 100ms，无限次）
结果：你只赢了一帧
```

除非你在外面死循环写（lab03 的 `hold`），否则永远追不上。而"进去"以后：

```
目标内部：新建一个线程，每 50ms 写 hp = 9999
结果：目标自己维持这个值，连你的程序退出了都还在
```

**这就是为什么真实外挂倾向注入**：持续、可复用、能做外部做不到的事（调 API、改代码、Hook）。

## 2. 五步，一步都不能少

| 步 | API | 要点 |
|---|---|---|
| 1 | 走链拿 `hp` 地址 | lab04/05 的成果，这里直接复用 |
| 2 | `OpenProcess` | 必须多要 `PROCESS_CREATE_THREAD`，否则第 5 步失败 |
| 3 | `VirtualAllocEx` | 在**目标**里申请内存，`PAGE_EXECUTE_READWRITE` |
| 4 | `WriteProcessMemory` | 把机器码字节写进去 |
| 5 | `CreateRemoteThread` | 起始地址 = 那块内存，目标就会新开一个线程跑它 |

注意第 3 步和第 4 步：`WriteProcessMemory` 我们 lab03 就会了，**新增的能力全在 `VirtualAllocEx` + `CreateRemoteThread` 这两个 API 上。**

## 3. 那 49 个字节在干什么

```asm
mov  rbx, <hp 地址>        ; 48 BB imm64
mov  r12, <Sleep 地址>     ; 49 BC imm64
loop:
mov  dword [rbx], <9999.0f>; C7 03 imm32
mov  ecx, 50               ; 睡 50 毫秒
and  rsp, -16              ; ← 栈对齐
sub  rsp, 32               ; ← 影子空间
call r12
add  rsp, 32
jmp  loop
```

这段是用 **gas 汇编 + objcopy** 生成的，不是手敲的十六进制。原因见下一节的两个坑。

### 坑 1：寄存器分"易失/非易失"

Windows x64 调用约定里，`rax / rcx / rdx / r8-r11` 是**易失**的——`Sleep` 返回后里面可能是垃圾。
我第一版把 hp 地址放在 `rax`、函数地址放在 `rdx`，结果**循环跑了两圈就崩**：
第二圈 `mov rax,[...]` 写到野地址。

正确做法：地址放 `rbx / r12 / r13` 这类**非易失**寄存器。

### 坑 2：栈必须 16 字节对齐

`call` 之前 `rsp` 必须是 16 的倍数（callee 里会用到对齐的 SIMD 指令）。
线程入口的 `rsp` 对齐状态不一定和你想的一样，所以先 `and rsp,-16` 一劳永逸，
再 `sub rsp,32` 给 callee 留影子空间。

**第一版我漏了这条，也是崩。** 定位方法：装一个 `AddVectoredExceptionHandler`，
把 `ExceptionAddress` 和 `Rip` 打出来——它会直接告诉你崩在机器码的第几个字节。

## 4. 实测输出（本机）

```
[+] 链校验通过：units = 00000000006BC4E0，hp 地址 = 00000000006BC4F0，当前 hp = 82.5
[+] 机器码 49 字节：hp 地址写死在 +2，Sleep 地址写死在 +12
[+] 目标进程里分配到的地址 = 0000000000650000（PAGE_EXECUTE_READWRITE）
[+] 远程线程已启动，句柄 00000000000000B8

   第  1 次：hp =     82.5        <- 注入前
   第  2 次：hp =   9999.0
   第  3 次：hp =   9999.0
   第  4 次：hp =   9999.0
   第  5 次：hp =   9996.5        <- 竞态窗口：目标刚减完，我们还没写
   第  6 次：hp =   9999.0
   ...
[+] 线程还在目标里跑。
```

`9996.5` 那几次不是错，是**两个线程在抢同一格**：目标每 100ms 减 2.5，我们每 50ms 写 9999。
读的瞬间正好落在"减完了、还没写回"的缝里。写得更快，缝就更小。

## 5. 一个必须知道的脆弱点

机器码里写死了 `Sleep` 的地址（`00007FF8772F0E50`）。之所以能跨进程用，是因为
**同一次开机里，系统 DLL 在所有进程中映射到同一个基址**。

但这依赖环境：换了系统、打了补丁、开了某些缓解措施，基址就可能不同。
工业级做法是在目标里**自己解析** `kernel32` 的导出表（PEB → Ldr → Export Table），
或者干脆注入 DLL、用 `GetProcAddress` 拿地址。那是下一层的事。

## 6. 自己动手

**实验 A · 加一个退出开关**
在目标里再申请一个字节当 flag，机器码每轮先 `cmp byte [flag],0` / `jne done`，
你这边把 flag 置 1，线程就自己 `ret` 结束。
（这一条做完，你就理解了"控制远程线程"的标准做法。）

**实验 B · 改频率看竞态**
把 `mov ecx, 50` 改成 10 或 500，观察 `9996.5` 出现的频率怎么变。

**实验 C · 改逻辑而不是改值**
把 `mov dword [rbx], 9999.0f` 换成"读 hp、加 1、写回"（需要 `movss` + `addss`）。
你会发现它写的是增量——这一步离"改代码"只有一步之遥。

## 7. 判定标准

> 不看文档，能自己写一个注入器：申请内存 → 写机器码 → 起线程 → 用读数证明它生效，
> 并且能说清"为什么地址要放在非易失寄存器里"和"为什么 `call` 前要 `and rsp,-16`"。

## 8. 常见坑

- **`CreateRemoteThread` 返回 0，`GetLastError = 5`**：`OpenProcess` 少了 `PROCESS_CREATE_THREAD`。
- **目标秒崩**：八成是寄存器或栈的问题，见 §3。用 VEH 打印 `Rip` 定位，别猜。
- **写进去了但 hp 不动**：地址算错了（链断了）或者目标每帧从别处重算——先确认链的终点。
- **以为机器码能随便搬**：任何 `rip` 相对寻址的指令搬过去都会指向错误位置。
  所以这里只用"立即数 + 寄存器"，不用全局变量、不调自己的函数。
- **在 64 位进程里注入 32 位机器码**（或反过来）：位数必须一致。
