# `p_ptr[1]` 为什么是 +4 字节，而不是 +1

- **日期**：2026-11-22
- **标签**：#指针 #结构体 #ghidra #类型

## 现象

`heal` 函数在 Ghidra 里反编译出来是这样：

```c
void heal(Player *p, int amount)
{
  int *p_ptr;
  int heal_val;

  *p_ptr = *p_ptr + heal_val;
  if (p_ptr[1] < *p_ptr) {
    *p_ptr = p_ptr[1];
  }
  return;
}
```

对应汇编：

```asm
1400014a7  MOV  EAX, dword ptr [RAX + 0x4]
1400014b2  MOV  heal_val, dword ptr [RAX + 0x4]
```

`p_ptr[1]` 和 `[RAX + 0x4]` 说的是同一件事。为什么？

## 原理：C 的下标运算就是指针加法

标准规定：

```c
p[i]  等价于  *(p + i)
```

关键在于 **`p + i` 加的单位不是字节，是 `sizeof(*p)` 个字节**。

```c
int *p;
p + 1;     // 地址 +4 字节，因为 sizeof(int) == 4
```

所以 `p_ptr[1]` = `*(p_ptr + 1)` = 地址 +4。

## 一个表看清

同一个地址偏移，用不同指针类型表达：

| 表达式 | 元素大小 | 实际字节偏移 |
|---|---:|---:|
| `((char *)p)[1]` | 1 | **+1** |
| `((short *)p)[1]` | 2 | **+2** |
| `((int *)p)[1]` | 4 | **+4** |
| `((Player *)p)[1]` | 40 | **+40 = 0x28** |

> `sizeof(Player)` 正好 40 —— 见 [docs/01-memory-layout.md](../docs/01-memory-layout.md)。

## 三种写法，一个地址

这是本条笔记最该记住的部分：

```c
p->max_hp
*(int *)((char *)p + 4)
((int *)p)[1]
```

**三者完全等价。** 分别是：

1. 结构体成员访问（最可读）
2. 字节偏移（最原始）
3. 整型数组下标（Ghidra 猜的类型）

逆向的工作就是：从 ② 或 ③ 还原成 ①。

## Ghidra 为什么写成 `p_ptr[1]`

因为 Ghidra **不知道 `p` 的真实类型**。

它只观察到：

```
[RAX]      被当作 4 字节读
[RAX + 4]  也被当作 4 字节读
```

于是推断：「这个指针指向一个 int 数组，第 0 和第 1 个元素」。

这个推断**在字节层面是对的**，但语义上错了——它不知道这是 `Player` 结构体的两个字段。

## 反例：类型猜错会怎样

假设把 `Player *p` 误当成 `Player *` 数组来理解，`p[1]` 就会算成 **+40**，直接读到结构体末尾之外。偏移全错，分析报废。

**所以逆向里「恢复类型」和「恢复偏移」同等重要。**

## 怎么修正

在 Ghidra 里给变量设成正确类型，代码会自动变干净：

1. `p_ptr` 右键 → `Retype Variable` → 输入 `Player *`
2. 重新反编译（`F5`）

`p_ptr[1]` 就会变成 `p->max_hp`，`*p_ptr` 变成 `p->hp`。

> 前提是 Ghidra 的项目里已经知道 `Player` 这个类型。带 `-g` 编译时 DWARF 会把结构体定义带进去；没有调试符号就得自己在 `Data Type Manager` 里手工建。

## 结论

1. `p[1]` 的偏移 = `sizeof(*p)`，不是 1。
2. 汇编里的 `+0x4` 与 C 里的 `p[1]`（当 `p` 是 `int *` 时）是同一个东西。
3. 看到 Ghidra 的数组下标写法，先查它推测的类型对不对。
4. **恢复类型 = 让偏移变成字段名 = 让代码变得可读。**
